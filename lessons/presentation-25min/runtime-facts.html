Protocol Information

  • Protocol Revision: 2026‑07‑28
  • Advertised as: supportedVersions: ["2026-07-28"]
  • JSON-RPC Version: 2.0
  • Transport: stdio
  • Lifecycle: stateless — no handshake, no session

Client Details

  • Name: inspector‑cli
  • Version: 2.5.0
  • Role: MCP Client
  • Declared per request in _meta, not once at startup

Server Details

  • Name: agent‑mcp‑workshop
  • Version: 0.0.1
  • Role: MCP Server (Java)
  • Identity travels in _meta["io.modelcontextprotocol/serverInfo"]

The Request Envelope

Carried in params._meta on every single request:

  • Required: io.modelcontextprotocol/protocolVersion
  • Required: io.modelcontextprotocol/clientCapabilities
  • Recommended: io.modelcontextprotocol/clientInfo
  • Optional: io.modelcontextprotocol/logLevel — absent means the server MUST stay silent on notifications/message

Missing a required field is -32602. This is what replaced the handshake.

Client Capabilities

Per-request facts, not session state — a client may send a different set on each call, and the server reads it fresh every time:

  • Roots: ✓ (listChanged: true)
  • Elicitation: ✓ (form, url)
  • Sampling: sent when the client can answer an embedded sampling/createMessage
  • Extensions: io.modelcontextprotocol/tasks, io.modelcontextprotocol/ui

Server Capabilities

Exactly seven optional slots, all of them: experimental, logging, completions, prompts, resources, tools, extensions. This server sets five.

  • Completions: ✓
  • Prompts: ✓ (listChanged: false)
  • Resources: ✓ (listChanged: false, subscribe: false)
  • Tools: ✓ (listChanged: false)
  • Extensions: ✓ (see next card)

Extensions

  • io.modelcontextprotocol/ui — mimeTypes: ["text/html;profile=mcp-app"]
  • io.modelcontextprotocol/tasks

Namespaced keys under capabilities.extensions — the old top-level tasks slot is gone, and unknown keys are ignored. See Extensions.

Result Shape

  • resultType on every result: complete, input_required, or task
  • Cacheable — also need ttlMs + cacheScope: tools/list, prompts/list, resources/list, resources/templates/list, resources/read
  • Must NOT carry them: prompts/get, tools/call, completion/complete
  • This server's hints: ttlMs: 60000, cacheScope: "public"

Error Codes

  • -32601 — removed method (deletion is physical: absence from the registry)
  • -32602 — incomplete _meta envelope
  • -32021 — missing client capability; data carries requiredCapabilities
  • -32022 — unsupported revision; data carries supported and requested

-32020…-32099 is now reserved for the spec; -32000…-32019 stays implementation-defined.

Removed Methods

All of these now answer -32601:

  • initialize, notifications/initialized
  • ping, logging/setLevel
  • notifications/roots/list_changed
  • resources/subscribe, resources/unsubscribe
  • tasks/result, tasks/list

Available Tools

  • Tool Name: key_word_search
  • Description: Searches for a specified keyword across all files in a project
  • Parameters: keyword (required), directory (optional) — omit the directory and the server asks over a round trip, then falls back to its working directory
  • UI: _meta.ui.resourceUri and _meta["ui/resourceUri"] → ui://keyword-search/mcp-app.html
  • No execution field — Tool.execution / taskSupport was removed

Available Prompts

  • Prompt Name: search_keyword
  • Description: Creates a prompt to search for a word using the key_word_search tool
  • Arguments: keyword (required)

Available Resources

  • Javadoc: 60+ HTML files
  • Example: javadoc/com/workshop/mcp/spec/Capability.html
  • MCP App: ui://keyword-search/mcp-app.html served as text/html;profile=mcp-app
  • Pagination: ✓ (nextCursor: "pageNext")

Round-Trip Details

  • Embeddable methods: roots/list, sampling/createMessage, elicitation/create — and nothing else
  • Shape: inputRequests is a keyed map; each entry has method + optional params, no jsonrpc, no id
  • Keys used here: search_roots, then search_directory
  • Elicitation: mode: "form"; the old elicitationId is gone
  • requestState: opaque string, base64 JSON of {keyword, stage}, echoed back byte-exact

Task Details

  • Trigger: the server's choice — no params.task opt-in exists, and one that arrives MUST be ignored
  • Gate: the client declared io.modelcontextprotocol/tasks on this request
  • Immediate reply: resultType: "task" with taskId, status working
  • TTL / poll: ttlMs: 300000, pollIntervalMs: 1000
  • Push: notifications/tasks on every status change, params = the full task snapshot

Subscriptions

  • Method: subscriptions/listen, one long-lived request carrying every notification
  • Filter fields: toolsListChanged, promptsListChanged, resourcesListChanged, resourceSubscriptions — no slot for tasks
  • Demultiplexed by: _meta["io.modelcontextprotocol/subscriptionId"], which holds the listen request's id
  • Honored here: nothing — this server's lists are fixed (listChanged: false), so the stream closes at once

Omit the subscriptionId from the acknowledgment and the client hangs forever, with no error and no timeout.

Request Flow

  • 1. server/discover — string id, no session created
  • 2. tools/list — cacheable, so ttlMs + cacheScope
  • 3. tools/call → input_required, embedding roots/list
  • 4. Retry with a new id, inputResponses, and the same requestState
  • 5. Roots empty? Escalate to an embedded elicitation/create and retry again
  • 6. Same call from a tasks-capable client → resultType: "task"
  • 7. tasks/get polled once a second until completed
  • 8. subscriptions/listen, acknowledged and closed

Tool Execution Results

  • Search Keyword: "record"
  • Search Directory: from the client's roots, or from the elicited directory
  • Files Matched: 1 (one small package, so the trace stays readable)
  • Result Shape: resultType: "complete" plus one text content block per file, path, keyword_count=N
