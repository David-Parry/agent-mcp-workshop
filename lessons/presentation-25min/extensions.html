Extensions in One Sentence

Anything not yet in the core spec lives under capabilities.experimental as a namespaced key. A client that does not recognise the key simply ignores it — so new features ship without breaking old clients.

What this server declares

"experimental": {
  "io.modelcontextprotocol/elicitation": {},
  "io.modelcontextprotocol/apps": {}
}

Identifier format

{vendor-prefix}/{extension-name}

  • Official: io.modelcontextprotocol/apps
  • Yours: com.acme/audit-trail

Elicitation — The Server Asks You

The key_word_search tool needs a directory to search. It is deliberately not a tool argument — the server gets it from roots/list. So what happens when the client hands back an empty roots list?

Lazy elicitation: the server does not fail and does not ask at startup. It waits until the first tools/call actually needs a directory, parks that call, asks the user, then resumes the parked call with the answer.
1
tools/call arrives — roots are empty, so the response is withheld (not answered, not errored).
2
Server sends elicitation/create (id -4000) with a JSON Schema describing the one field it wants.
3
Client renders a form; the user picks a directory.
4
Answer comes back as action: "accept"; the server adds the directory to its roots set.
5
The parked tools/call resumes and answers with the real search results — the client never knew it waited.

Request

{
  "id": -4000,
  "method": "elicitation/create",
  "params": {
    "message": "Pick a directory for the
       keyword-search tool to search in:",
    "requestedSchema": {
      "type": "object",
      "required": ["directory"],
      "properties": {
        "directory": {
          "type": "string",
          "title": "Search Directory"
        }
      }
    }
  }
}

Response

{
  "id": -4000,
  "result": {
    "action": "accept",
    "content": {
      "directory": "/Users/.../agent-command"
    }
  }
}

Three possible actions: accept, decline, cancel. Only accept carries content.

Why Negative Request IDs?

Server-initiated requests use a reserved negative id range so they can never collide with client ids. Each flow gets its own block, which makes a raw trace readable at a glance.

Reserved IDServer-initiated request
-1000roots/list
-2000sampling/createMessage
-4000elicitation/create

Open the Trace Log and the ids tell you who started each exchange.
