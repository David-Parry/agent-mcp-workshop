The Idea in One Sentence

Instead of holding a JSON-RPC request open until the work completes, the receiver immediately replies with a task handle and runs the work in the background. The requestor polls (tasks/get) and later retrieves the actual result (tasks/result) — on its own schedule, even across reconnects.

Three terminal states. Receivers MUST NOT move a terminal task back to working.

Capabilities — Both Sides Opt In

Server declares

  "capabilities": {

      "cancel": {},

      }
    }
  }
}

Client declares

{
  "capabilities": {
    "tasks": {
      "list": {},
      "cancel": {},
      "requests": {

        "elicitation": { "create": {} }
      }
    }
  }
}

Five New Methods

MethodPurpose
tools/call + taskAugmentation — opts the call into deferred execution
tasks/getPoll current status without blocking
tasks/resultBlock until terminal, return underlying result
tasks/listPaginated list of tasks
tasks/cancelBest-effort cancel (-32602 if already terminal)
notifications/tasks/statusOptional push from receiver on status change
