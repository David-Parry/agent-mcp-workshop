Why This Matters

The Inspector proves the protocol works. It does not show value — a keyword count is not an insight. Wrapping the same MCP tool in a plugin of skills turns "58 files contain TODO" into "this router is your debt hotspot, and here is why."

Supervised agent: the agent does the tedious work — searching, analysing, cross-referencing — then stops and asks before producing the consequential output. You stay the decision maker.

Four Skills, Three Layers

Data

keyword-search

Calls the key_word_search MCP tool and sorts files by count.

Analysis

keyword-report

Groups hits by package, finds concentration, writes a markdown report.

Execution

java-script-runner

Runs a single .java file with no build step (JEP 330) — ships an embedded FileAnalyzer.

Orchestrator

audit

Drives the other three, reasons about the hotspot, pauses at the checkpoint.

The Audit Workflow

/keyword-audit-plugin:audit — or with your own list: keywords=[TODO,FIXME,HACK]

1
Search — key_word_search once per keyword, via MCP.
2
Identify — the file with the highest single-keyword count is the hotspot.
3
Analyze — run FileAnalyzer on the hotspot through the JVM.
4
Read + reason — read the source and explain why that file leads.
5
Report — per-keyword breakdown with concentration figures.
⏸ Checkpoint — "Proceed to synthesis? (yes/no)" — nothing is written until you say yes.
6
Synthesis — health score, prioritised actions, then offers to save audit-report.md.

Skill vs Plugin

A skill is one folder

skills/keyword-search/
  SKILL.md    ← name, description,
                 instructions

A plugin bundles skills

keyword-audit-plugin/
  .claude-plugin/plugin.json
  skills/
    keyword-search/  keyword-report/
    java-script-runner/  audit/

Skills are plain markdown — the interesting engineering is the MCP server underneath. Launch both together with ./start_claude_mcp.sh, which builds the JAR, resolves mcp.json into .mcp-resolved.json, and passes --plugin-dir.

Live Demo
