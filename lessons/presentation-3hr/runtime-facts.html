Runtime Facts — Pre-recorded Session Reference

Protocol Information

  • Protocol Version: 2026‑07‑28 (stateless — no initialize, no session)
  • JSON-RPC Version: 2.0
  • Transport: STDIO
  • Communication: Client→server requests only — a server MUST NOT send one

Client Details

  • Name: inspector‑cli
  • Version: 2.5.0
  • Role: MCP Client
  • Identity: re-declared in _meta per request — nothing persists between them

Server Details

  • Name: agent‑mcp‑workshop
  • Version: 0.0.1
  • Role: MCP Server
  • Runtime: JVM / Java 21

Client Capabilities

Sent in _meta on every request — there is no handshake to remember them

  • Roots: ✓ (listChanged: true)
  • Elicitation: ✓ (form and url)
  • Extensions: tasks, ui

Server Capabilities

From the server/discover result

  • Tools: ✓ (listChanged: false)
  • Prompts: ✓ (listChanged: false)
  • Resources: ✓ (listChanged: false, subscribe: false)
  • Completions: ✓
  • Extensions: ui + tasks

Declared Extensions

  • io.modelcontextprotocol/ui — mimeTypes: ["text/html;profile=mcp-app"]
  • io.modelcontextprotocol/tasks — {}

Under capabilities.extensions, not experimental.

Available Tools

  • Tool Name: key_word_search
  • Description: Searches for keywords across project files
  • Parameters: keyword (required), directory (optional) — omit the directory and it comes from roots/list or the elicitation form, falling back to the server's working directory
  • Task Support: the server's call, per request — execution.taskSupport no longer exists
  • MCP App: ui://keyword-search/mcp-app.html (under both _meta.ui.resourceUri and _meta["ui/resourceUri"])

Available Prompts

  • Prompt Name: search_keyword
  • Description: Creates a prompt to search for a word using the key_word_search tool
  • Arguments: keyword (required)

Available Resources

  • Resource Count: 70+ Javadoc files
  • Resource Type: HTML documentation
  • Example: javadoc/com/workshop/mcp/spec/Capability.html
  • Pagination: ✓ (nextCursor: "pageNext")
  • UI Resource: ui://keyword-search/mcp-app.html

Elicitation Details

  • Method: elicitation/create — embedded in a result, never sent as a request
  • Carrier: inputRequests.search_directory of an input_required result
  • Mode: "form" (the alternative is "url")
  • Message: "Pick a directory for the keyword-search tool to search in"
  • Schema Fields: directory (absolute path)
  • User Response: comes back as inputResponses.search_directory on the next tools/call
  • Correlation: the echoed requestState — no elicitationId, no request id
  • Declined: the server stops asking and searches its own working directory

Message Flow

No handshake, no session — just requests

  • 1. server/discover — versions, capabilities, identity
  • 2. Tools discovery
  • 3. Resources discovery (+ templates)
  • 4. Resource reading
  • 5. Prompts discovery
  • 6. Prompt execution
  • 7. Tool call → input_required (embedded roots/list)
  • 8. Retry under a new id, carrying inputResponses
  • 9. Escalation to elicitation, if roots came back empty
  • 10. Task handle → tasks/get polling
  • 11. subscriptions/listen → acknowledgment
